# Habit Tracker API (Дементьева Юлия)

## Зачем этот API

Чтобы мобильное приложение и веб-клиент могли создавать привычки и вести их список, а каждый пользователь видел и менял только свои.

## Что в репозитории

- `api.yaml` — спецификация OpenAPI 3.0
- `service/` — каркас сервиса, сгенерированный по спеке (python-flask)
- `README.md` — этот файл

## Эндпоинты

| Метод | Путь | Что делает | Ошибки |
|---|---|---|---|
| GET | `/habits` | список своих привычек (`archived`, `limit`, `offset`) | 401 |
| GET | `/habits/{habitId}` | одна привычка | 401, 403, 404 |
| POST | `/habits` | создать привычку (201) | 400, 401 |
| PATCH | `/habits/{habitId}` | изменить привычку | 400, 401, 403, 404 |
| DELETE | `/habits/{habitId}` | удалить привычку (204) | 401, 403, 404 |

Про ошибки:
- **401** - токен не передан или невалиден.
- **403** - токен валидный, но привычка чужая.
- **404** — привычки с таким id нет.

DTO в `components/schemas`: `Habit` (то, что отдаём наружу), `HabitCreate`, `HabitUpdate`, `Frequency`, `Error`. Внутренние поля (`ownerId`, `deletedAt` и т.п.) в схемах отсутствуют, наружу не едут.

## Как делала

**Модель:** Claude Sonnet 5.5 (Anthropic) помогала придумать список эндпоинтов, помогла оформить ридми.

**Команда кодогена:**

```
java -jar openapi-generator-cli.jar generate -i api.yaml -g python-flask -o service
```

Генератор отработал без ошибок. Были только предупреждения `WARN`: он временно переименовал `habitId` в `habit_id` (имена в Python) и вернул обратно, на результат это не влияет.
